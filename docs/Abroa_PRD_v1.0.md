# Abroa 产品需求文档（PRD）

- 版本：v1.0
- 日期：2026-11-24
- 状态：产品决策已确认，待实施
- 项目：Abroa（基于 we-promise/sure 的独立开源产品）
- 产品形态：Web + PWA；官方云端与自托管并存
- 开发顺序：后端优先，后端完整验收后再进行前端改造
- 本文为产品范围和验收的依据；具体代码路径、数据库字段及接口以 P0 源码审计和后续技术规格为准。

## 1. 产品定位与目标

Abroa 面向全球各国留学生及其家庭，提供一站式跨境财务管理。它不是单纯的记账工具，而是在真实个人财务数据之上，统一管理留学费用、生活费、家庭资助、预算、外币资产及未来资金需求。

学生可以独立使用，也可以邀请家长参与财务规划；家长可以独立注册，在孩子出国前制定计划。产品不限制学生来源地或目的地；地区差异通过配置和金融数据接入渠道解决，不为每个国家开发独立产品。

品牌：Abroa，源自 Abroad。英文标语：Manage your money, wherever life takes you. 品牌替换须保留原项目许可证、版权及归属声明，正式发布前核查商标和域名。

### 1.1 产品解决的问题
- 账户分散在不同国家、银行、支付平台及货币中，缺少统一的财务视图。
- 学费、房租、生活费、保险、签证等有不同缴费周期，月度记账不足以进行完整规划。
- 家长拨款用途和学生实际支出难以对应，且学生需要保留财务隐私。
- 换汇、跨境转账、代付和退款容易导致重复记账或统计失真。
- 学生及家长需要提前知道资金还能使用多久、何时需要补充、剩余留学成本是多少。

### 1.2 产品原则
- 复用 Sure 成熟的财务基础设施，保留其全部原有高级功能；按需隐藏，不删减。
- 核心功能开源免费，云端可通过托管、银行连接服务、AI 服务及商业技术支持收费。
- 以真实账务为准，财务计算使用确定性算法；AI 不充当账务计算权威。
- 不持有、划转、兑换真实资金，不提供银行、支付、信贷或投资交易服务。
- 默认保护个人隐私，家长协作建立在明确、可撤销的授权上。
- 优先完成可验证的后端业务及接口，不以模拟数据、空壳接口或 UI 占位作为功能完成。

## 3. 用户、空间与权限

### 3.1 用户身份
学生、家长、平台管理员是三类使用角色，不必绑定成固定的一人一角色。注册支持邮箱和 Google；复用原有认证、会话、邮箱验证、密码重置及可用的账户安全机制。Google 登录应安全关联身份，避免凭未验证邮箱自动合并账号。无家长关联的学生仍拥有完整个人财务功能。

### 3.2 独立空间及项目授权
学生拥有自己的财务空间，家长拥有自己的财务规划空间和经授权可见的子女视图。允许一个学生关联多个家长，一个家长关联多个学生。家长关系不是财务数据所有权，也不自动取得 Sure 家庭管理员的全部权限。学生财务租户边界必须保留；禁止通过共享 family 或 admin 角色绕过授权。关联通过明确邀请、接受或撤销实现，并记录状态和操作时间。

| 共享对象 | 规则 |
|---|---|
| 学生私人账户、原始余额、交易明细 | 默认不共享；可显式授权到指定范围 |
| 分类汇总、可支配生活费、预算执行、费用计划、预警 | 学生可以按项目、类别及资源授权 |
| 家长参与的拨款记录、提议及确认 | 仅相关双方可见；不自动公开学生银行交易 |
| 管理指定预算、资金池、费用计划 | 学生显式授权后允许操作 |
| 学生银行凭证、AI 凭证、安全设置 | 不向家长共享 |
| 其他留学项目或无关资源 | 未授权则禁止访问 |

默认家长管理模式为 B：提出计划，学生确认后生效。学生可主动启用 C：允许家长直接管理指定预算及财务计划。读权限、提议权限与直接编辑权限独立，支持随时撤销。撤销后后续 API、导出、AI 查询及异步任务均不得继续读取授权范围外的数据。任何共享、修改及撤销保留审计记录。

家长独立注册后可创建未关联孩子的规划草稿，录入计划费用、预算及拨款安排。孩子注册并明确接受关联及计划后才纳入其正式项目，不自动创建或修改他人的实际财务数据。

### 3.3 首次使用流程
1. 邮箱或 Google 注册/登录；选择学生或家长使用入口。
2. 设置语言、时区、来源地、当前居住地、统计币种；允许后续修改。
3. 学生创建留学项目（目的地、学校、就读时间、项目主要币种）；无留学项目也可使用个人账本。
4. 引导连接银行、导入账单或手动创建账户。
5. 可设置预算、费用及资金池，可邀请家长；非必要步骤允许跳过并在以后补充。
6. 家长可先创建规划或邀请学生，接受授权后进入家长视图。
7. 初始化中断后可继续，重复提交不创建重复账户或项目。

## 4. 个人财务核心与 Sure 复用

完整保留账户、账本、收入支出、转账、分类、标签、商户、备注、附件、搜索、交易拆分、对账、规则、预算、目标、周期性账单、现金流、资产负债、投资及高级报表等原有能力。保留原有 API、数据导入导出、国际化、权限、后台任务等兼容性。具体预览功能及现有实现状态须通过本地源码和测试核实，不将文档中的功能描述视为已通过验收。

个人账户可包括现金、银行存款、信用卡、贷款、电子钱包、投资、其他资产及负债。账户按原有类型管理，附加所属地区、币种、来源等必要属性。付款渠道（支付宝、微信、Apple Pay 等）与真实扣款账户分开建模，不能将使用支付渠道等同于持有独立余额账户。

原有财务记录仍是唯一账务事实来源。留学模块、家长视图、报表和预测读取经过授权的同一套账务数据，不新增重复的真实交易表作为第二账本。高级功能继续存在，默认简洁模式按需隐藏。

## 5. 留学项目（STUDY）

- STUDY-01：一个用户可创建多个项目，记录名称、来源地、目的地国家/城市、学校、计划起止日期、学年/学期设置、统计币种及状态（规划中、进行中、结束/归档）。
- STUDY-02：账户可关联至项目作为资金来源，交易可显式归属项目或保持个人用途。一个账户可以服务多个项目；不可仅因账户关联便把其所有交易重复归属各项目。交易跨项目分配使用明确拆分，合计不超过原金额。
- STUDY-03：独立汇总学费、住宿、日常生活费、奖学金、家庭资助、累计成本、待支付费用、预算执行与未来资金缺口。
- STUDY-04：项目归档后保留账务历史、报告及授权状态，不删除个人账户或真实交易；归档项目可按权限恢复。
- STUDY-05：预算、费用、虚拟资金池、家长协作、预测及报告均可按项目过滤；同一交易在个人总账只计算一次。

验收：同一学生创建两个不同币种项目及个人支出；共享账户、跨项目拆分、项目归档后，各项目和个人总账均准确，另一项目及家长无越权读取。

## 6. 全球金融数据接入（CONNECT）

### 6.1 接入方式
海外银行自动同步优先复用 Sure 已有连接器及后台同步机制；实际支持国家、金融机构、认证方式、可用性、费用以服务商覆盖及合同为准，不承诺所有银行均能自动接入。新增统一接入边界，兼容原有 Provider，不重复开发原有渠道。

本阶段新增支付宝、微信及国内常见银行的账单导入能力；P0 根据真实文件样例确定支持的银行与格式清单，不声称支持未验证的模板。支付宝、微信以账单导入为主，不假设存在可用的个人消费历史自动同步 API。其他地区可用 CSV、Excel、PDF 通用导入及自定义字段映射；不能接入的账户可手工管理。自托管用户可自行配置金融数据服务商凭证。

### 6.2 统一处理流程
接入源 -> 原始文件/同步记录 -> 解析与标准化 -> 账户识别 -> 重复检测 -> 交易方向及类型判定 -> 分类/项目/资金池建议 -> 高置信度入账或待确认 -> 对账 -> 记录结果及撤销能力。

标准化保留来源、外部交易 ID（如有）、日期时间、原币金额、方向、商户/描述、交易状态、支付渠道、真实资金账户、来源文件及行标识。保留退款、撤销、跨币种转账等关系；原始文件按用户数据保留与删除规则处理。缺失资金来源时不能编造账户。

### 6.3 自动记账与待确认
- CONNECT-01：银行已确认交易、明确分类规则等高置信度记录可自动入账，重复同步必须幂等。
- CONNECT-02：同一来源的稳定外部 ID 与文件指纹用于精确去重；跨来源匹配结合日期、金额、币种、方向、账户及商户等证据。模糊匹配不能仅凭金额和日期自动删除交易。
- CONNECT-03：支付宝/微信由银行卡真实扣款时，同一次消费只计一次；补充支付渠道等元数据并保留来源链路。钱包余额实际支付时记入对应钱包账户。
- CONNECT-04：账户、分类、归属或匹配有疑问的记录进入待确认列表；用户可确认、更正、忽略、拆分或撤销自动处理。真实账务确认和分类待确认应分别建模，避免重复记账或漏报余额。
- CONNECT-05：退款关联原交易，转账匹配两侧账户，家长拨款与实际到账记录核销。未到账计划不计入真实余额。
- CONNECT-06：导入批次展示成功、失败、待确认、重复及错误原因；提供预览、重复导入防护、可追溯回滚。回滚不得删除无关的用户修改。
- CONNECT-07：同步具备状态、重试、错误诊断、限流及凭证保护；管理后台可查看健康状态和服务成本，不泄漏私人财务明细。
- CONNECT-08：用户可调整自动化程度；低置信度交易必须有明确确认或保留未分类状态的机制。

验收：同一银行记录重复同步、同一文件重复导入、银行与支付渠道重复消费、同日同额真实不同交易、部分退款、跨币种转账、并发重试及异常文件等测试；实际支出、余额与对账结果一致，无重复扣减。

## 7. 多币种与跨境财务（FX）

学生、家长、留学项目各自设置统计/显示币种，显示设置不改变账户或真实交易币种。保留历史原币金额、交易时间、汇率来源及所用汇率；历史消费采用交易时汇率，当前资产使用最新可用估值汇率。汇率缺失或过期必须明确标识，不能按 1:1 静默计算不同币种。金额及汇率使用精确十进制定点计算，并遵守各币种精度，禁止用二进制浮点直接计算账务。

实际换汇记录原币扣款、目标币到账、实际成交汇率、手续费及关联转账；报价与实际成交分开。手续费明确计为支出，不重复包含在转账金额中；汇率导致的资产估值变化不计为日常消费。预算和资金池可采用多币种，报告在统一统计币种下汇总并保留原值。家长不同显示币种不意味着共享更多数据。

验收：人民币转英镑、美元账户消费、手续费、历史汇率与当前汇率差异、汇率缺失、不同小数位货币、学生/家长不同报告币种；原始金额不变，转账不计收入/消费，汇兑估值与实际费用明确区分。

## 8. 多层级预算（BUDGET）

采用留学总预算 -> 学年 -> 学期 -> 月度 -> 消费分类预算的可选层级，并支持自定义时间范围。任何层级都不是强制项，用户可以只建一个学年预算与月度生活费预算。保留 Sure 原有月度预算及高级功能。

- BUDGET-01：设置项目、周期、日期范围、预算币种、分类、限额、所属上级、是否滚存及预警阈值。
- BUDGET-02：同一真实交易可计入符合条件的不同层级执行情况，但各层级不能相加作为实际总支出；同级重叠预算须明确统计口径，不能重复扣减。
- BUDGET-03：区分计划额度、实际消费、已承诺未支付费用、已预留资金、可用额度。预留不等于消费；支付后释放对应预留并核销费用，避免重复扣减。
- BUDGET-04：支持预算调整、滚存、超支提醒、上级预算与下级分配一致性检查；超额分配应提示，不能篡改真实交易。
- BUDGET-05：家长可提出预算修改，学生确认后执行；直接编辑必须具备明确授权；版本化记录变更和撤销。
- BUDGET-06：退款、交易修改、归属变更、汇率修正应重新计算相应执行情况。

验收：设置总/学年/学期/月预算后发生同一消费，所有适用预算更新，真实支出只记一次；固定费用预留、支付、退款、跨期和滚存结果准确。

## 9. 虚拟资金池与家长拨款（FUND）

资金池用于分配真实可用资金，不改变银行账户余额，不是支付账户。可建立学费、房租、生活费、应急备用金等用途池，也可自定义。支持项目、币种、资金来源、目标额度、实际分配、已占用及可用资金。

- FUND-01：用户可从真实资金余额划分虚拟额度；内部划拨、用途调整不创建银行交易。系统防止同一真实余额被多个资金池重复承诺，并明确未分配、已分配和缺口。
- FUND-02：费用计划可占用指定资金池；消费、退款、费用取消或调整按关联关系释放或核销资金，避免重复扣减。
- FUND-03：家长可创建一次性、周期性或分期拨款计划，指定预计金额、币种、时间、项目、用途及资金池。支持学生确认、拒绝、修改建议及提醒。
- FUND-04：拨款状态区分计划、已确认计划、部分到账、已到账、取消等；由学生确认或匹配真实银行到账，支持多个实际交易匹配一个计划。未匹配到账不得计入真实余额。
- FUND-05：同一到账交易只核销一次；不同币种拨款保留原计划及实际到账、汇率、费用与差额。
- FUND-06：家长只能查看相关拨款计划及授权汇总；不能通过到账匹配获得未经授权的银行交易详情。

示例：学生实际收到 100,000 元，分配学费 50,000、房租 25,000、生活费 20,000、应急金 5,000；真实余额仍为 100,000 元，自由生活费为 20,000 元，实际支付学费后才发生真实账户扣款。

验收：计划不影响余额，部分到账、币种差额、重复匹配、资金池调整、固定费用支付及退款均准确，授权撤销后不允许家长继续编辑。

## 10. 留学费用管理（FEE）

复用 Sure 周期性账单、分期及提醒机制，统一管理学费、住宿、签证、保险、交通、教材、考试及其他费用。每条费用关联项目、类别、账期、原币金额、支付截止日、付款计划、预算、资金池及实际付款记录；支持一次性、周期性和分期费用。

- 学费：按学年/学期，支持分期、奖学金、减免及实付金额；奖学金直接抵扣应付与实际到账奖学金收入分别处理，不重复抵减。
- 住宿：房租周期、押金、合同到期及退款。可退押金按实际财务性质记录为资产或应收，不能默认全部作为不可退消费。
- 签证、保险：申请/续签、保费与保障期限。
- 交通和其他费用：机票、通勤、回国费用、教材、考试费、申请费等。

FEE-01 至 FEE-05：支持草稿/待支付/部分支付/已支付/逾期/取消，以及退款记录与剩余应付重新计算；分期与总费用的关系清晰；已支付金额从关联真实交易计算；到期提醒、部分支付、提前支付、减免及退款可追溯；账单、预算、资金池和实际账务不重复计费。

验收：学费分期、奖学金减免、房租续期、可退押金、部分付款及退款的待付金额、现金流和净消费一致。

## 11. 财务预测与风险预警（FORECAST）

使用确定性算法，综合已确认账户余额、可用资金池、历史消费趋势、未来账单、预计拨款及汇率情景。预测不是真实余额，不保证未来结果。明确数据时间、假设、缺失数据和估计范围；历史不足时使用用户提供的预算或标记无法可靠估算，不编造历史数据。

| 能力 | 输出 |
|---|---|
| 资金续航 | 当前可支配生活费还能覆盖的预计天数 |
| 未来余额 | 未来 30/90/180 天预计现金流与余额轨迹 |
| 资金缺口 | 预计何时余额不足、缺口金额及原因 |
| 拨款建议 | 建议补款时间与金额，区分已确认和不确定拨款 |
| 留学总成本 | 已发生成本、未来已知费用、估计剩余费用 |
| 汇率风险 | 剩余外币费用对用户指定汇率变化的敏感度 |
| 消费异常 | 相对历史/预算的异常消费与解释 |
| 情景模拟 | 房租变化、生活费变化、汇率变化、拨款延迟等 |
| 应急资金 | 备用金阈值与预警 |

基础预测 = 起始可用现金 + 预计流入 - 预计流出；历史日常消费基线应剔除内部转账、已单独建模的固定费用及他人代付等，避免重复计入。区分保守情景（不含未确认拨款）和包含计划拨款的情景；固定费用、退款及汇率假设可检查。资金池额度不是新增资产。AI 可以解释结果和提出调整建议，不替代计算。家长只接收授权范围内的预测和风险提示。

验收：用固定日期、固定汇率和已知现金流构建可手算测试场景，覆盖零消费、无历史、负余额、费用逾期、拨款延迟、多币种及变更后重新计算；结果可复现。

## 12. 个人代付及应收应付（RECEIVABLE）

本阶段仅做 B：个人管理他人欠款和自己的应付款，不做多人共享账本。允许录入联系人昵称、用途、原始垫付交易、个人承担部分、他人承担部分、币种、到期日、已结算金额及状态，不要求对方注册。

- 代付时银行实际减少全部款项，只有个人承担部分属于个人消费；其他部分计入应收。
- 他人为用户垫付时，用户个人承担部分确认相应费用与应付；实际还款核销应付，不重复计消费。
- 支持部分还款、多笔匹配、跨币种结算、差额、取消和退款；采用 Sure 可兼容的账户/交易拆分和资产负债机制。
- 预留将来多人分账扩展的数据关系，不提前实现共享账本、多人实时结算或真实付款。

验收：垫付 800 英镑，个人承担 200，另三人共欠 600；银行减少 800、个人消费 200、应收 600。对方返还 200 后应收为 400，返款不计新增收入，净资产和现金流口径正确。

## 13. AI 财务助手（AI）

复用 Sure 的 AI 对话、分类、账单识别、工具调用及现有接入机制。提供自定义 API URL、API Key、模型名称及必要的模型能力配置，兼容现有支持的协议，并以 OpenAI-compatible 接入为优先验证目标。用户可关闭 AI；未配置模型或服务故障不影响核心财务业务。

- AI-01：回答授权范围内的账户、交易、费用、预算及预测问题，提供个性化分析、建议及风险解释。
- AI-02：辅助分类、导入识别和匹配建议；按交易确认机制执行，低置信度结果不能直接覆盖真实数据。
- AI-03：自然语言提出预算调整、分类、资金分配、费用或拨款计划变更；展示变更前后、影响范围与理由，用户明确确认后才执行交互式写操作。
- AI-04：确认与执行分离；执行时重新校验权限、资源版本及确认内容，防止重复提交、过期确认及越权。操作留痕，支持安全撤销或补偿操作。
- AI-05：家长 AI 仅能访问授权资源，不能通过提示词、工具调用或摘要间接获取未授权交易。服务端独立鉴权，不依赖模型自觉。
- AI-06：模型凭证加密、不进入普通日志；用户自定义 API 地址需有合理网络访问限制与防 SSRF 设计，兼顾自托管显式配置的本地模型。提示词和工具不授予任意代码执行、真实支付权限。
- AI-07：记录服务调用量、成功率、费用（若可取得）与套餐额度。外部模型不可用时提供明确错误及重试，不虚构结果。

验收：模拟模型提供确定响应，测试建议/拒绝/确认/执行/撤销、重复确认、资源并发修改、越权工具调用、恶意导入文本、凭证泄露及模型异常。使用用户明确配置的真实模型进行可用性验证。

## 14. 报表、通知与本地化（REPORT / NOTIFY / I18N）

报表复用 Sure 现金流、资产负债、净资产、分类消费、收入支出、可筛选期间及导出能力，新增留学项目/学年/学期报告、费用执行报告、资金池、拨款及换汇成本报告。个人、项目及家长授权视图使用一致口径；父母不能从导出、筛选、错误响应或细粒度聚合反推出不允许访问的数据。

通知渠道仅站内通知和邮件。事件包括费用到期/逾期、预算预警、资金缺口、待确认交易、拨款提议/到账、授权邀请/撤销、同步失败等。支持用户偏好、已读状态、时区、幂等发送、重试与失败记录；邮件默认避免暴露敏感金额或明细，链接打开后重新验证身份和权限。PWA push 暂非要求，保留原有能力。

多语言、货币、时区、日期及数字格式独立配置；保留 Sure 的国际化基础，新增文案使用翻译键。学生来源地、项目目的地、当前居住地、账户所属地区分别设置；连接器、默认分类和学期模板根据地区配置，允许用户自定义。全球开放注册不代表每国金融服务已经可用；按实际服务范围及上线地区核查条款、隐私和数据保留要求。

## 15. 用户端产品形态（后端验收后实施）

学生端默认简洁模式：总览（可用资金、预算、待缴费用、预警）、账户、账本、留学项目、预算/资金池、费用、家长协作、预测、AI、设置。专业模式展示原有投资、资产负债、贷款、规则、高级报表等全部高级能力；自定义模式可配置首页、导航与功能模块。切换模式不删除数据，不改变授权。

家长端独立导航：已关联学生/规划草稿、授权概览、学费生活费计划、拨款、待确认提议、风险及报告、AI、设置。无授权时只展示自己创建的规划和相关协作记录。

管理员端独立导航及权限体系，不混入学生财务空间。Web 响应式适配和 PWA 安装、更新、缓存策略后续实施；敏感财务内容不得因共享设备或缓存绕过登录。保留原有设计组件、重新设计页面和交互。后端阶段仅保留运行、调试和验收所必需的原有 UI，不提前重写前端。

## 16. 商业化与管理员后台（ADMIN）

核心财务、留学、家长协作及高级功能开源免费，官方云端与自托管共用核心。自托管自行配置金融服务商、模型、存储及邮件，不能因为没有官方订阅而失去核心财务功能。官方云端可提供托管、自动同步、AI 及备份等有成本的增值服务；商业技术支持可收费。具体套餐价格、免费额度、支付服务商、结算币种与退款政策后续确定。

| 管理模块 | 需求 |
|---|---|
| 用户与账号 | 查询用户账号状态、角色、封禁/解封、账号生命周期 |
| 套餐及订阅 | 可配置权益、额度、订阅状态、订单、退款及优惠基础数据模型；未选支付服务商前不启用真实扣费 |
| 银行服务 | 服务商配置、地区覆盖、同步健康、调用量及成本 |
| AI 服务 | 模型及用量配置、额度、调用状态、成本 |
| 导入管理 | 解析模板版本、失败分类、诊断和服务质量 |
| 运营分析 | 注册、活跃、留存、转化等必要运营指标；不采集私人财务用于公共统计 |
| 运维管理 | 服务状态、任务队列、日志、备份恢复及配置 |
| 地区配置 | 语言、货币、地区、渠道与政策配置 |
| 权限审计 | 管理员角色权限、操作记录、安全事件、数据导出/删除请求处理 |

管理员默认无权查看用户银行余额、交易明细和私人规划。平台运营权限与财务租户权限独立。日志、统计、支持诊断应脱敏。自托管允许隐藏官方商业运营模块，但保留必要系统管理。公开留学成本数据库管理功能待对应后续模块实施。

验收：管理员操作须经过独立授权并记录审计；非管理员不可访问；管理员也不能因平台角色直接访问任意用户财务 API；自托管无订阅亦可完成全部核心流程。

## 17. 安全、数据与非功能性要求

采用已确认的 A 为主：复用 Sure 的身份认证、会话、原有权限、安全机制、数据加密及凭证管理，不另建整套安全平台。针对新增业务补充必要授权、数据隔离、审计与回归测试。P0 核实已有机制及缺口，不把未验证安全特性写成已实现。

- 继承 AGENTS.md 的 Current.user / Current.family 约束，所有新增请求、导出、后台任务、AI 工具、通知均执行资源级权限校验。
- 保证学生/家长/管理员之间及不同项目之间的数据隔离；授权撤销、用户封禁及账号删除处理缓存、任务和访问凭证。
- 关键财务写操作使用数据库事务、必要唯一约束及并发控制；导入、同步、通知、拨款核销、AI 执行均需幂等。
- 继承加密、凭证保护、安全日志及备份机制；不提交密钥、用户账单或生产数据。使用合成样例或经授权脱敏样例测试。
- 可导出、删除个人数据，明确共享记录及法定/必要保留的边界；按实际上线地区评估合规要求，不以功能完成等同合规认证。
- 不强制端到端加密，因为后端需要同步、预测和自动记账；应核实传输及敏感字段保护。
- 金额、时区、汇率、账务统计、批量数据及并发场景需有自动化测试。列表分页、批次后台处理及查询索引应适合长期账务使用。
- 测试环境与生产隔离，任务重试不得重复入账，升级及备份恢复不得损坏原有数据。性能目标以 P0 的真实 Sure 基线确定，不捏造现有吞吐量。

## 18. 技术架构原则

以 Sure 当前 Fork 为基础，采用模块化二次开发（C），仍为单体 Ruby on Rails + PostgreSQL + Redis 架构；复用现有后台任务、API、鉴权、财务模型、组件及 Docker 配置。版本及实际依赖以仓库锁定文件为准。避免微服务化和重复实现。新增领域模块尽量通过关联、服务、扩展接口或独立业务表接入现有核心，必要时允许直接修改核心并补回归测试。

初步数据领域（逻辑名称，非最终表名）：留学项目/项目归属、家庭协作关系/授权/提议、预算周期及分配、虚拟资金池及分配事件、拨款计划及到账匹配、留学费用及分期/支付关联、接入源及导入批次/标准化记录/确认任务、换汇信息、代付及结算、预测快照/情景、通知、AI 操作提议及确认、商业权益及用量、审计。优先复用存在的实体；禁止复制 Sure 总账、认证及财务计算引擎。最终表、索引、约束、迁移策略及 API 需 P0 后写入技术规格。

保留上游 Git 关系，建议使用独立开发分支、小范围提交、定期合并上游并跑全量测试。保留 AGPLv3、原始版权、基于 Sure/Maybe Finance 的声明及不隶属原品牌的说明；为网络用户提供相应源代码获取方式。品牌重命名不删许可证。

仓库规范：遵循根目录 AGENTS.md；变更前阅读 docs/llm-guides/architecture.md 和相应任务指南；Minitest 用于行为测试，RSpec/rswag 用于 OpenAPI 文档，新增 API 遵守现有 X-Api-Key 规范并更新 OpenAPI。未经明确环境操作授权，不自动运行迁移、不启动 Rails 服务，不触碰凭证。Docker Compose 为最终部署方式，复用并核实原项目 Web、Worker、PostgreSQL、Redis 服务，支持自托管和官方云端，配置持久化卷、环境变量、健康检查、备份/恢复及版本升级说明。

## 20. 验收与开发执行规范

### 20.1 需求完成定义
每个需求须具备：可运行的真实实现、必要数据库约束和迁移（在授权测试环境验证）、访问权限、错误处理、自动化测试、API 文档（如涉及接口）、状态记录及与已有功能的回归验证。只生成接口、空函数、静态数据或仅写文档均不算完成。不能用删除测试、放宽财务精度、跳过权限校验或改变业务含义来使测试通过。

### 20.2 必测跨模块流程
1. 学生邮箱/Google 登录，创建两个项目，导入不同币种账户，核实个人及项目财务。
2. 银行同步和支付平台账单同时出现一笔消费，精确去重，修正模糊匹配，退款后重算。
3. 学生建立学年/学期/月度预算及资金池，家长提出定向拨款，学生确认；部分到账和学费分期支付后正确核销。
4. 家长查看授权汇总、申请修改、获得指定直接编辑权后撤销；尝试通过接口、报表、AI 和异步任务绕过权限均失败。
5. 学生代付房租并收到部分还款，消费、应收、银行余额及现金流一致。
6. 未来账单、历史消费和拨款变动触发预测及通知；汇率变动不重复计支出。
7. AI 提出预算调整，用户拒绝/确认/撤销，重复请求与过期确认不产生重复写入。
8. 管理员运营操作不暴露财务数据；无付费套餐的自托管环境可运行核心功能。
9. 原 Sure 数据升级、新安装、备份恢复、后台任务重试及上游原有功能回归。

## 21. 后续计划与未决事项

后续优先实现公开成本数据库：依据政府、大学等可核查来源维护地区和学校成本参考，标记来源、时间、币种、适用范围与更新时间。此后才考虑自愿匿名消费统计，需独立授权、最小样本量及反识别措施，不能直接公开或收集用于公共统计的个人交易明细。另行建设多人共享账本。
